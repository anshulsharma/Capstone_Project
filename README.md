# Mamaearth Returns & Growth Intelligence Pipeline

A three-layer pipeline that finds where returns are eroding margin on Mamaearth orders:
a SQL layer (reporting), a pandas layer (cleaning and analysis), and a GenAI layer
(a business narrative for ops and finance heads).

## How the layers connect

- **Part 1 (SQL)** loads the three CSVs into MySQL and produces report results.
  It does not feed the other layers directly.
- **Part 2 (Python)** reads the same raw CSVs from `data/` independently, so it can run
  without the database. It writes `narrator/findings.json` at the end of
  `clean_and_eda.py`, and `visualize.py` reads that file to draw the charts.
- **Part 3 (GenAI)** reads `narrator/findings.json` only. It never computes a number itself.

Every figure in the narrative therefore traces back to the Part 2 calculation.

## Part 1: SQL layer

1. Open MySQL Workbench and connect to your local server.
2. Run `sql/schema.sql`. It creates the `mamaearth` database and the three tables.
3. Run `sql/seed_data.sql`. It loads the CSV data.
4. Run `sql/reports.sql`. It contains nine report queries, each with its expected output in a comment.

Expected row counts: `customers` 45, `products` 16, `orders` 180.

| Report | Expected result |
|---|---|
| a) Totals | 180 orders, revenue 99,860.20, AOV 554.78 |
| b) COUNT(rating) | 180 total, 165 rated, 15 unrated |
| c) No-order customer | C045 Vihaan (both queries agree) |
| d) Cities with return rate > 20% | Jaipur 42.1, Lucknow 30.6, Bangalore 24.2 |
| e) Top 5 spenders | C043, C026, C008, C011, C042 |
| f) Category revenue | Haircare 44,956.10; Skincare 27,346.00; Babycare 16,805.00; PersonalCare 10,753.10 |
| g) Names starting with A | 10 |
| h) Distinct acquisition sources | 4 (Ad, Organic, Referral, Social) |
| i) Loyalty tier | Gold 28, Silver 17 |

Run `schema.sql` and `seed_data.sql` only on a fresh database. Re-running `reports.sql`
query (i) after it has run once fails, because the column already exists. To reset, run
`DROP DATABASE IF EXISTS mamaearth;` and start again.

## Part 2: Python analysis

```bash
python3 analysis/clean_and_eda.py    # cleans data, prints every step, writes narrator/findings.json
python3 analysis/visualize.py        # writes the two PNGs in visualizations/
```

Run both from the repo root. They read only the CSVs in `data/`, so they can be run any time.

Key results printed by `clean_and_eda.py`:

| Step | Result |
|---|---|
| Payment casing | 7 raw variants become CARD 70, UPI 55, COD 55 |
| Duplicates | 5 removed (O0176–O0180), leaving 175 rows |
| Rating median (before imputing) | 3.0 |
| Cleaned total order value | 97,358.30 |
| Reconciliation delta | 2,501.90, exactly the value of the 5 duplicates |
| IQR outliers on quantity | O0011 (25) and O0098 (30), flagged and kept |
| Return rate by payment | COD 44.4%, CARD 14.7%, UPI 18.9% (hypothesis confirmed) |
| Highest-risk segment | COD orders in Tier 2 cities, 54.5% |
| Correlations | All pairs negligible; "higher discounts reduce returns" is busted (r ≈ -0.09) |
| True peak month (outliers excluded) | March 2026, 20,318.90 |

January looks like the peak only when the two bulk orders are included.

## Part 3: GenAI narrator

```bash
python3 narrator/generate_narrative.py
```

- **With a key:** set `GEMINI_API_KEY` as an environment variable, then run the script.
  Mac/Linux: `export GEMINI_API_KEY="your-key"`.
- **Without a key:** the script falls back to the offline template. It needs no network
  access or configuration, and it produces the same numbers.

The narrative is printed and checked against six required figures. Each should print PASS.

To verify the saved sample without calling the API:

```bash
python3 narrator/generate_narrative.py --check-sample
```

`narrator/sample_output.txt` was generated by the offline path on 18/10/2026.

## Reproducing everything from scratch

1. `sql/schema.sql` → `sql/seed_data.sql` → `sql/reports.sql` (MySQL Workbench)
2. `python3 analysis/clean_and_eda.py`
3. `python3 analysis/visualize.py`
4. `python3 narrator/generate_narrative.py`

The data files in `data/` are the originals and must not be edited. All cleaning happens in code.
